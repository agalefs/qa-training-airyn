# Test Design: RR-501 Rental Price and Deposit

## 1. Input Partitions (Equivalence Partitioning)

### Rental Days Partitions
* **EP-DAYS-INV-01 (Invalid - Below Minimum):** `days <= 0` (e.g., `0`, `-1`)
* **EP-DAYS-VAL-01 (Valid - Standard Rate, 0% Discount):** `1 <= days <= 2`
* **EP-DAYS-VAL-02 (Valid - Short Term, 10% Discount):** `3 <= days <= 6`
* **EP-DAYS-VAL-03 (Valid - Medium Term, 15% Base Discount):** `7 <= days <= 13`
* **EP-DAYS-VAL-04 (Valid - Long Term, 20% Base Discount):** `14 <= days <= 30`
* **EP-DAYS-INV-02 (Invalid - Above Maximum):** `days >= 31` (e.g., `31`, `50`)
* **EP-DAYS-INV-03 (Invalid - Non-Whole Numbers / Data Type):** Decimals (e.g., `2.5`), strings (e.g., `"five"`), or null/empty values

### Customer Type Partitions
* **EP-CUST-VAL-01 (Valid - Standard Customer):** Customer record has `contractor_credit = false` (pays 20% deposit, no extra contractor discount)
* **EP-CUST-VAL-02 (Valid - Contractor Credit Account):** Customer record has `contractor_credit = true` (`$0.00` deposit, `+5%` discount on rentals `>= 7` days)
* **EP-CUST-INV-01 (Invalid - Unrecognized/Missing Customer):** Null customer record or invalid flag state

## 2. Boundary Value Analysis (BVA)

### Boundaries Identified for Days
* **Lower Invalid/Valid Boundary:** `0` | `1`
* **Band 1 / Band 2 Boundary:** `2` | `3`
* **Band 2 / Band 3 Boundary (Also Contractor 5% threshold):** `6` | `7`
* **Band 3 / Band 4 Boundary:** `13` | `14`
* **Upper Valid/Invalid Boundary:** `30` | `31`

### Boundaries Identified for Money Rounding (Half-Up at 3rd Decimal)
* **Round Down Threshold:** `.xx4` (e.g., `10.124` $\rightarrow$ `10.12`)
* **Half-Up Threshold:** `.xx5` (e.g., `10.125` $\rightarrow$ `10.13`)
* **Double-Rounding Check:** Discounted total ends in `.xx5` (rounds up), and 20% of that rounded total also ends in `.xx5` (rounds up again).

## 5. Time-Pressure Triage (30 Minutes Before Release)

### Top 5 Cases to Run First (With Risk Reasoning)
1. **`TC-501-06` (`BVA` - 7-day Contractor):** High financial leakage risk—verifies the exact boundary where the 5% contractor bonus activates, stacks with the 15% tier, and waives the deposit.
2. **`TC-501-11` (`BVA` - Half-Up Rounding):** High accounting/ledger risk—verifies two-step half-up rounding (`199.325` $\rightarrow$ `199.33`, then deposit rounding), which is a prime source of penny-discrepancy defects.
3. **`TC-501-01` (`BVA` - 0-day Invalid):** High operational/revenue risk—prevents clerks from accidentally generating free (`$0.00`) rentals or causing division-by-zero errors.
4. **`TC-501-10` (`BVA` - 31-day Invalid):** High inventory/policy risk—enforces the maximum 30-day rental cap so equipment isn't locked out beyond policy limits.
5. **`TC-501-15` (`DT` - Standard Customer 10-day):** High baseline revenue risk—confirms the primary happy-path calculation (base discount + 20% deposit collection) works end-to-end.

### What is Left Unrun (Accepted Risk)
* **Interior partition representatives & remaining band boundaries** (`TC-501-03`, `TC-501-04`, `TC-501-07`, `TC-501-08`, `TC-501-09`, `TC-501-16`, `TC-501-17`): If the 7-day threshold and 10-day calculation pass, adjacent arithmetic tiers (`10%`, `20%`, `25%`) likely share the same lookup table logic.
* **Sub-half rounding down (`TC-501-12`):** Lower financial impact (1-cent variance) compared to half-up regulatory/accounting rules.
* **Non-integer/decimal input (`TC-501-13`):** Assuming UI input controls restrict entry to whole numbers or backend schema validation rejects floats.
