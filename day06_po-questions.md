# Day 6 Product Owner Questions — RentRight v1.4 Security & Authorization

- **Role check vs. state/validation order (`403` vs. `409` / `422`):** When a rental does not meet the `Returned` and late-fee `> 0` conditions on `PATCH /rentals/{id}/late-fee`, `409 Conflict` is returned before role authorization is evaluated. Should role/authorization checks (`401`/`403`) always run before business-state (`409`) and payload-validation (`422`) checks so callers cannot infer rental state?
- **`403 Forbidden` vs. `404 Not Found` for cross-customer object IDs:** When a customer requests or acts on another customer's rental ID (`GET /rentals/{id}` or `POST /rentals/{id}/cancel`), should denied cross-customer requests consistently return `403 Forbidden`, or does the spec/product prefer `404 Not Found` on any endpoints to avoid confirming ID existence?
- **Clerk exception or threshold for late-fee waivers:** Rule `W1` states late-fee waivers are `Admin only`, while `clerk1` received `200 OK` on `PATCH /rentals/{id}/late-fee`. Aside from fixing `403 Forbidden`, is there any business scenario where a `clerk` should be allowed to waive a late fee (for example, below a set dollar amount or with manager/admin sign-off)?
- **Token expiration & demo token behavior (`tok-expired-demo`):** For pre-expired (`tok-expired-demo`) or malformed bearer tokens across all endpoints, should every protected endpoint uniformly return `401 Unauthorized` with a generic error message?
- **Multi-step rental lifecycle preconditions in automated tests:** Creating a rental starts it in `Reserved` status and requires activation before returning to accrue a late fee (`Returned` with `lateFee > 0`). Should the test environment/API provide a reset or fixture helper for `Returned` late-fee rentals so authorization tests do not depend on chaining `Create` -> `Activate` -> `Return`?
