# Test Design: RR-503 Checkout Options

## 1. Parameters and Constraints

* **Item class (`I`):** Light (`L`), Heavy (`H`), Specialty (`S`)
* **Fulfilment (`F`):** Pickup (`P`), Delivery (`D`)
* **Payment (`Pmt`):** Card (`Cd`), Invoice (`Inv`), Cash (`Cs`)
* **Customer (`C`):** Retail (`R`), Contractor (`Ct`)
* **Constraint:** Heavy items (`H`) cannot be paid in Cash (`Cs`).
* **Total Valid Combinations:** $(3 \times 2 \times 3 \times 2) - (1 \times 2 \times 1 \times 2) = 36 - 4 = 32$.

## 3. Pair-Coverage Check Table

| Parameter Pairs | Covered Value Combinations |
| :--- | :--- |
| **Item Class** $\times$ **Fulfilment** | `(L,P)`, `(L,D)`, `(H,P)`, `(H,D)`, `(S,P)`, `(S,D)` — *All 6 valid pairs covered* |
| **Item Class** $\times$ **Payment** | `(L,Cd)`, `(L,Inv)`, `(L,Cs)`, `(H,Cd)`, `(H,Inv)`, `(S,Cd)`, `(S,Inv)`, `(S,Cs)` — *All 8 valid pairs covered (`(H,Cs)` excluded per constraint)* |
| **Item Class** $\times$ **Customer** | `(L,R)`, `(L,Ct)`, `(H,R)`, `(H,Ct)`, `(S,R)`, `(S,Ct)` — *All 6 valid pairs covered* |
| **Fulfilment** $\times$ **Payment** | `(P,Cd)`, `(P,Inv)`, `(P,Cs)`, `(D,Cd)`, `(D,Inv)`, `(D,Cs)` — *All 6 valid pairs covered* |
| **Fulfilment** $\times$ **Customer** | `(P,R)`, `(P,Ct)`, `(D,R)`, `(D,Ct)` — *All 4 valid pairs covered* |
| **Payment** $\times$ **Customer** | `(Cd,R)`, `(Cd,Ct)`, `(Inv,R)`, `(Inv,Ct)`, `(Cs,R)`, `(Cs,Ct)` — *All 6 valid pairs covered* |

## 4. Additional Non-Pairwise Test Cases (Run on Top of Pairwise Set)

* **ID:** `TC-503-11` | **Technique:** `EP` *(Negative Constraint)* | **Priority:** `P1`
  * **Title:** Negative Constraint Test: Heavy Item with Cash Payment (`Heavy`, `Pickup`, `Cash`, `Retail`)
  * **Preconditions:** **User:** `clerk_01`. **Item:** `ITEM-311` (Class: `Heavy`, Status: `Available`). **Data:** Customer `CUST-RET-01` (`Retail`). **Clock:** `2026-11-17 11:50`.
  * **Steps:** 1. Add `ITEM-311` (`Heavy`) to cart. 2. Select `Pickup`. 3. Attempt to select `Cash` payment and submit checkout.
  * **Expected Result:** System blocks transaction and displays validation error ("Heavy items cannot be paid in cash"), or disables the Cash option in the UI.

* **ID:** `TC-503-12` | **Technique:** `DT` *(Multi-Factor Business Rule)* | **Priority:** `P2`
  * **Title:** High-Risk Multi-Factor Interaction: `Heavy` + `Delivery` + `Invoice` + `Retail`
  * **Preconditions:** **User:** `clerk_01`. **Item:** `ITEM-312` (Class: `Heavy`, Status: `Available`). **Data:** Customer `CUST-RET-01` (`Retail`, non-contractor). **Clock:** `2026-11-17 11:55`.
  * **Steps:** 1. Add `ITEM-312` (`Heavy`) to cart. 2. Select `Delivery` fulfilment. 3. Select `Invoice` payment for a `Retail` customer. 4. Submit checkout.
  * **Expected Result:** Verifies whether a Retail (non-contractor) customer is permitted to combine high-risk Heavy equipment delivery with deferred Invoice billing without an upfront deposit or credit line.

### Why Pairwise Alone Does Not Cover Them
1. **Negative Constraints (`TC-503-11`):** Pairwise generation deliberately excludes invalid pairs (such as `Heavy` + `Cash`) to minimize test count. Explicit negative testing is required to confirm the constraint is actually enforced rather than silently accepted.
2. **3-Way and 4-Way Risk Interactions (`TC-503-12`):** Pairwise guarantees every *2-way* pair is tested, so `(H,D)`, `(D,Inv)`, and `(Inv,R)` are all covered individually across different rows—but never together in a single transaction where credit risk (`Retail` + `Invoice`) compounds with logistics risk (`Heavy` + `Delivery`).
